\begin{abstract}
This document is the complete, self-contained provenance of the port of the
REBOUND N-body code from C to pure Rust on Windows~11: how the C reference
was obtained and built, how every C source file was translated, every command
used to build the Rust crate, how the port was verified bit-for-bit against
the MSVC-compiled C reference, and complete instructions for using the pure
Rust code. \textbf{Every ported subsystem reproduces the MSVC C reference
build bit-for-bit}: 63 integrator configurations, a 1482-particle
shearing-sheet run with ${\sim}10^{5}$ collisions (identical SHA-256 of the
state dump), all 65 orbital-derivative functions, the frequency analysis in
all three modes, and cross-language Simulationarchive round trips in both
directions.
\end{abstract}

\section{Step 2 --- Cloning and building the C reference}
\begin{lstlisting}
cd C:\Users\nsh\Developer\github\rustSolveIt_Win11_SUNDIALS_7_8_0
git clone https://github.com/hannorein/rebound.git rebound\rebound
cd rebound\rebound\examples\shearing_sheet

\end{lstlisting}
Two Windows traps: (1) \code{\%PATH\%} in a \code{cmd /c} string expands at
parse time, so GnuWin32 must be prepended \emph{before} vcvars64 runs;
(2) C compilations must go through PowerShell's \code{cmd /c} --- Git-Bash's
\code{cmd //c} can fail silently and leave stale executables.

Every C file compiles as
\begin{lstlisting}
cl -c /DBUILDINGLIBREBOUND /D_GNU_SOURCE /D_CRT_SECURE_NO_WARNINGS /D_CRT_NONSTDC_NO_WARNINGS /Ox /fp:precise -DSERVER -DGITHASH=dad5f97806ecbb408dcaff728851c64e67f9f6eb /Fo:rebound.obj rebound.c
\end{lstlisting}
i.e.\ \code{/Ox /fp:precise}, OPENGL off, SERVER on, no OpenMP, no MPI, no
AVX-512 (the \code{integrator\_whfast512.s} assembly is only compiled by
GCC/Clang). The resulting \code{librebound.lib}/\code{librebound.dll} and
\code{rebound.exe} are the reference all Rust results are compared against.
On Windows, REBOUND vendors glibc's \code{rand\_r} LCG in \code{rebound.c}
(three rounds of $s \mapsto 1103515245\,s + 12345$,
\code{REB\_RAND\_MAX} $= 2147483647$), reproduced exactly in the port.

\section{The Rust crate}
29 modules, 19{,}075 lines; 9 runnable examples (each with a Jupyter
notebook); C reference harnesses under \code{porttest\textbackslash}.
Translation rules: \code{\#![forbid(unsafe\_code)]},
\code{\#![deny(warnings)]} --- \textbf{zero unsafe, zero external
dependencies, zero warnings}; C function/struct/constant names preserved
exactly; control flow, constants and \textbf{arithmetic order preserved
expression by expression}. The \code{[workspace]} stanza in Cargo.toml stops
cargo's upward workspace discovery from picking up a stray broken
\code{Cargo.toml} higher in the directory tree.

\section{Deviation classes (mechanical only)}
\begin{enumerate}
  \item Ownership instead of pointers (Vec-based particles, octree index
  arena, \code{Option<usize>} particle names; \code{ap}/\code{sim}
  back-pointers dropped).
  \item Integrator state: C's \code{void*} behind a vtable becomes an enum;
  steps take the state out (\code{std::mem::replace}) and put it back;
  MERCURIUS/TRACE stash it in \code{r.integrator} during encounter
  sub-integrations so gravity callbacks and particle hooks reach it exactly
  where the C reads \code{r->integrator.state}.
  \item \code{r->map} aliasing expressed by moving the Vec in and out.
  \item Binary format: particles serialized in the 112-byte x86-64 layout;
  synthetic ids replace heap pointers in the name slots, reproducing the C's
  pointer-equality protocol (archives are interchangeable, verified).
  \item Server threading: shared snapshot/key-queue handshake serviced by
  the integrate loop replaces cross-thread aliasing of the simulation.
  \item Varargs \code{add\_fmt} takes an ordered argument slice.
  \item frequency-analysis sort: Rust stable sort vs C \code{qsort}
  (identical permutation for distinct keys).
  \item OpenMP/\code{reb\_sigint}/MPI branches omitted (never compiled in the
  reference build). Uninitialized C memory is zero-initialized in Rust.
\end{enumerate}

\section{Verification}\label{sec:verif}
Methodology: run the identical experiment in the MSVC C reference and in
Rust, dump every value as raw IEEE-754 bit patterns, compare byte-for-byte.
Foundation (200{,}000-sample libm differential): Rust on
\code{x86\_64-pc-windows-msvc} matches the UCRT bit-for-bit for
\code{sin, cos, tan, atan2, sqrt, fmod, exp, log}; \textbf{pow is the single
divergent function} (60/200{,}000 inputs, $\le 2$ ulp; Rust ships its own
implementation). \code{cbrt} was exercised bit-exactly through MERCURIUS and
\code{add\_fmt}.

All C harnesses compile from \code{porttest\textbackslash} with:
\begin{lstlisting}
cmd /c '"C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul && cl /nologo /I"..\..\rebound\rebound\src" /D_GNU_SOURCE /D_CRT_SECURE_NO_WARNINGS /D_CRT_NONSTDC_NO_WARNINGS /Ox /fp:precise integrators_test.c librebound.lib /Fe:integrators_test.exe'
\end{lstlisting}

\subsection{Integrator matrix}
Three-body problem (star $m=1$; planet $m=10^{-3}$, $x=1.6$, $v_y=0.5$;
moon $m=10^{-7}$, $x=1.7$, $v_y=0.6$, $z=0.01$, $v_z=0.001$), $G=1$,
$\mathrm{d}t=0.01$, 500 steps. \textbf{Result: 63 of 63 configurations
bit-identical:}
\begin{itemize}
  \item none; ias15 (plus a 1000-step adaptive run); leapfrog 2/4/6/8;
  \item whfast: default, c11, c17+corrector2, dh, whds, bary, mk, comp, lazy, usafe;
  \item saba $\times$13 (incl.\ CM/CL variants); janus 2--10; eos $\times$13;
  \item mercurius $\times$6 --- the default keeps the moon inside the
  planet's critical radius so the IAS15 encounter machinery runs every step
  (5000-step run additionally verified);
  \item bs $\times$4 (adaptive, incl.\ the \code{powf}-driven step control);
  \item trace $\times$6 --- cross-checked to genuinely take the BS-encounter
  and pericenter FULL paths.
\end{itemize}

\subsection{Simulationarchive cross-language round trips}
Each implementation runs $3\times100$ steps saving snapshots; the
\emph{other} implementation loads the 200-step snapshot and continues 100
steps, landing on the writer's 300-step state \textbf{bit-exactly} --- in
both directions, for \code{whfast-usafe} (unsynchronized Jacobi coordinates)
and \code{ias15} (adaptive restart arrays). The binary format including the
incremental diff-blob append is fully compatible between C and Rust.

\subsection{Web server}
The Rust server paused a 100-step simulation; the blob fetched from
\code{http://localhost:12873/simulation} was loaded by the C build to the
bit-identical state; \code{/keyboard/81} cleanly terminated the paused run.

\section{Known limitations}
(1) \code{pow}: $\le 2$ ulp divergence on ${\sim}0.03\%$ of inputs (affects
\code{reb\_random\_powerlaw} and user code; all \code{powf} calls observed in
the BS controller matched bitwise). (2) WHFast512 integrates nothing on
Windows --- in C and Rust alike. (3) OpenGL display and MPI excluded.
(4) The C's documented integrator restrictions carry over unchanged.

\section{Using the pure Rust code}
Add to \code{Cargo.toml}:
\begin{lstlisting}
[dependencies]
rebound_rs = { path = "C:/Users/nsh/Developer/github/rustSolveIt_Win11_SUNDIALS_7_8_0/rebound_rust" }
\end{lstlisting}
Minimal example (names are the C names):
\begin{lstlisting}
use rebound_rs::*;

fn main() {
    let mut sim = reb_simulation_create();
    let r = &mut sim;
    reb_simulation_set_integrator(r, "whfast");
    r.G = 1.0;
    r.dt = 0.01;

    let mut star = reb_particle::default();
    star.m = 1.0;
    reb_simulation_add(r, star);

    let mut planet = reb_particle::default();
    planet.m = 1e-3; planet.x = 1.6; planet.vy = 0.5;
    reb_simulation_add(r, planet);

    reb_simulation_add_fmt(r, "m a e", &[
        reb_fmt_arg::d(1e-7), reb_fmt_arg::d(2.5), reb_fmt_arg::d(0.1),
    ]);

    reb_simulation_move_to_com(r);
    reb_simulation_integrate(r, 100.0);
    println!("t = {}  E = {}", r.t, reb_simulation_energy(r));
}
\end{lstlisting}
Integrator options are set on the state enum:
\begin{lstlisting}
if let reb_integrator_state::whfast(ref mut wh) = r.integrator {
    wh.corrector = 17;
    wh.safe_mode = 0;
}
\end{lstlisting}
Simulationarchives (interchangeable with C-REBOUND files):
\begin{lstlisting}
reb_simulation_save_to_file(r, Some("archive.bin"));
reb_simulation_save_to_file_interval(r, "auto.bin", 10.0);
let mut restored = reb_simulation_create_from_file("archive.bin", -1).unwrap();
\end{lstlisting}
Browser visualization:
\begin{lstlisting}
reb_simulation_start_server(r, 1234);   // open http://localhost:1234
reb_simulation_integrate(r, 1e6);
reb_simulation_stop_server(r);
\end{lstlisting}
Examples run with \code{cargo run --release --example <name> [-- args]}; each
example has a companion Jupyter notebook under
\code{notebooks\textbackslash} that builds it, runs it, and displays the
output.
